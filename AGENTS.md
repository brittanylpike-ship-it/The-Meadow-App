# The Meadow UI Constitution

## No Placeholder UI Rule

Status: Permanent

The Meadow is not a React Native application. The Meadow is a designed world. Implementation technology must be invisible.

Before building any screen, ask:

If all borders were removed, would this still feel like The Meadow?

If the answer is no, the screen fails.

## Core Law

Users should never perceive views, cards, containers, forms, panels, default buttons, default inputs, default layouts, React Native demo layouts, or Expo placeholder layouts.

Users should perceive places, pages, plaques, landmarks, storybook spreads, and environments.

## Forbidden Patterns

Do not create centered login cards, generic forms, Material UI layouts, Bootstrap layouts, dashboard layouts, admin layouts, landing page layouts, marketing page layouts, hero image plus form layouts, website layouts, React Native demo layouts, component showcase layouts, or default Expo layouts.

## Screen Design Law

Every screen must begin as a place, not a component hierarchy.

Authentication is the Entry Gate. Frozen Ground is a winter place. Crossroads is an autumn place. Memory Garden is a living garden. Hearth is a shared room.

The place comes first. The UI comes second.

## Component Law

Components must disappear into the experience.

Buttons should feel like plaques, markers, offerings, or invitations.

Inputs should feel like journal spaces, parchment fields, or memory spaces.

They must never feel like default TextInput components.

## React Native Law

React Native is implementation only. It is never visual direction.

Never build View to Card to Form to Button and attempt to style afterward.

Build Place to Composition to Experience to Components.

## Acceptance Test

Show the screen to someone unfamiliar with the project.

If they say, "Nice app," the screen fails.

If they say, "This feels like a place," the screen passes.

## Definition Of Done

The user forgets React Native exists.

The user feels: I entered The Meadow.
